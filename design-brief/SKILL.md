Write structured design briefs that align stakeholders and guide execution. Based on agency-standard brief formats from IDEO, Pentagram, and industry practice.

## Structure

1. Project overview: what is being designed and why
2. Problem statement: what specific problem this design solves
3. Objectives: measurable outcomes for this project
4. Target audience: who it is for, what they need, what they value
5. Scope: what is included and what is explicitly excluded
6. Deliverables: exactly what will be produced (format, quantity, specs)
7. Timeline: phases, milestones, review points, final delivery
8. Success criteria: how we know it is done well
9. Constraints: budget, technology, brand, legal

## Sections Detail

Project overview should be 2-3 sentences. If it takes longer to explain, the project is not defined well enough.

Problem statement should be from the user perspective, not the business perspective. "Users cannot find the checkout" not "We need to redesign the checkout page."

Objectives must be measurable. "Improve conversion by 15%" not "Improve the experience."

Target audience needs: demographics, behaviors, goals, pain points, existing solutions they use. Avoid vague "everyone" targeting.

## Anti-Patterns

| Mistake | Consequence | Fix |
|---------|-------------|-----|
| Problem stated as solution | Team builds the wrong thing | Describe the problem, not the fix |
| No constraints given | Design that cannot be built | List technology, budget, timeline limits |
| Vague success criteria | No way to know when it is done | Define specific, testable criteria |
| Scope creep hidden in "also" | Timeline and budget blown | List exclusions clearly |

## Headline Formula

| Pattern | Example | Best for |
|---------|---------|----------|
| How to [verb] [noun] | "How to Design REST APIs in 2026" | Tutorials |
| [Number] [noun] for [audience] | "10 React Patterns for Senior Engineers" | Lists |
| Why [common belief] is [wrong] | "Why Microservices Are Not the Answer" | Opinions |
| From [X] to [Y] | "From Zero to 1M Requests with FastAPI" | Case studies |
| [Topic]: A Complete Guide | "API Authentication: A Complete Guide" | Reference |

## Lead Paragraph

- Restate the problem the reader has
- Hint at the solution
- Set expectations (what they will learn)
- Maximum 3 sentences
- No dictionary definitions, no "In today's world"

## Code Examples

- Only show relevant lines, not the full file
- Syntax highlighting (always)
- Line annotations for complex blocks
- Runnable code (no pseudo-code)
- Error examples alongside correct ones
- Copy button for convenience

## SEO Fundamentals

- Primary keyword in H1, first paragraph, and one H2
- Meta description: under 155 characters, includes value prop
- Alt text on all images (descriptive, not keyword-stuffed)
- Internal links to 2-3 related posts
- External links to authoritative sources (MDN, docs, papers)
- URL: kebab-case, matches H1, no stop words

## Content Rules

- Write for skimmers: short paragraphs, clear headings, bold key terms
- Show, don't tell: use examples over explanations
- One level of depth: don't explain fundamentals in a post for experienced devs
- Version numbers: include them, update them, mark deprecation

# README Artisan

Crafts READMEs that people actually read. Not template filler. Based on analysis of the top 50 GitHub repositories by stars.

## The Hook

First paragraph answers: what is this in 5 words, who is this for, why does this exist. Three sentences, not ten.

Bad: A React component library for building modern user interfaces.
Good: Buttons, modals, forms, done right. No design debt.

## The Demo

After the hook, show a 3-line code example, an ASCII diagram, or a screenshot. Never start with installation instructions. Let them see it first.

## Features

Every feature must be quantified or comparative.

Bad: Fast, lightweight, easy to use.
Good: 2KB gzipped. Zero dependencies. One API that works in React, Vue, and vanilla JS.

## The Why Section

One paragraph explaining the decision behind the project. Builds trust. Helps people decide if your tradeoffs match theirs.

## Tone by Project

| Project type | Tone |
|-------------|------|
| CLI tool | Direct, confident |
| Library | Helpful, thorough |
| Design system | Opinionated |
| Personal project | Honest, humble |
| Company OSS | Professional, warm |

## Anti-Patterns

Generated by copilot look. Screenshots of code just show the block. Coming soon features ship or remove. Ignoring mobile most READMEs read on phones. Badges that dont link anywhere just noise.
